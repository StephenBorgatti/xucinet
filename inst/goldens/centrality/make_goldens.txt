// ===========================================================================
// xucinet golden fixtures - Chapter 9, centrality
//
// Produces the UCINET numbers the chapter 9 routines are written against:
// xdegree, xeigenvector, xbeta, xcloseness, xbetareach, xreach, xbetweenness,
// xhubsauthorities, xpncentrality, xinduced, xcentrality, and 2-mode
// centrality. (Twelve, not thirteen: xreachbetweenness was withdrawn on
// 7 Sep 2026 - it has no UCINET equivalent.)
//
// HOW TO RUN
//   1. Open UCINET.
//   2. In the command line box at the bottom of the main window:
//        ->cd <this folder>
//        ->run make_goldens.txt
//   3. Then do PART B, which is four menu runs and takes a couple of minutes.
//   4. Commit everything UCINET writes into this folder, plus two logs:
//        log_make_goldens.txt   the session log for PART A
//        log_menu.txt           one continuous log covering PART B
//   5. Tell me the version number from Help | About.
//
// Last run: 6-7 September 2026, UCINET 6.849. Every line ran. PART B run 1
// matched the layout predicted from uc_DegreeCentrality.pas exactly, so the
// source tree is the binary and the remaining routines can be written from the
// Delphi. Results and both logs are in this folder.
//
// THE SEVEN INPUTS, all already in this folder as ##h/##d pairs
//   campnet          binary, directed, 18 nodes        the everyday case
//   davis            2-mode, 18 women by 14 events     the 2-mode case
//   sampson          10 relations, 18 nodes            the multi-relation case
//   g9_disc          disconnected, 12 nodes            star + path + triangle
//   g9_iso           3 isolates + a 7-node core        degree 0, no distances
//   baker_journals   valued, directed, 20 nodes        the valued case
//   newguinea        Alliance + Opposition, 16 nodes   the negative-tie case
//
// g9_disc and g9_iso were built by make_inputs.R in this folder; the other five
// are the shipped datasets, written out so UCINET can be pointed at one
// directory and nothing outside it is touched. g9_disc has three components of
// different size and shape on purpose, so the four Freeman options for
// undefined distances give four different answers rather than coinciding.
//
// WHAT THIS FILE IS FOR, AND WHAT IT IS NOT FOR
//   Numbers, at full precision. Not layout.
//
//   The printed layout is read from the Delphi instead, which Steve pointed out
//   on 6 September 2026 is both easier and better. Everything a centrality
//   routine prints comes from two shared places: the tlogfile header helpers,
//   where putstr right-pads each label to the single constant pwidth, and
//   tmat.display in utmat.pas, which is the algorithm cat_uci_matrix() in
//   R/output.R reproduces. A log shows one path through a routine that branches
//   on six dialog controls - graphtype, raw, normalized, edgeweights,
//   wtdnormalization, excludediagonal - and the source shows all six. The units
//   are vendored in inst/reference/delphi/ so the derivation stays checkable.
//
//   Reading them has already corrected three things a single log would have
//   left wrong: the headings are Degree / Outdeg / Indeg with an "n" prefix for
//   the normalized pass, not NrmDegree, and there is no Share column; graph
//   centralization is a second titled matrix at four decimals, a proportion and
//   not a percentage; and both the raw and the normalized columns are optional,
//   so a four-column table is the default tick state rather than a fixed shape.
//
//   So PART A is the whole of the automated work. PART B exists only because
//   the source tree is not the binary you are running - it is four runs to
//   confirm that what I am reading is what you have installed.
//
// WHY PART A CANNOT COVER EVERYTHING
//   Only six of the thirteen routines exist as command-language functions.
//   Closeness, Reach, Beta Reach, Hubs and Authorities, Induced, 2-Mode
//   Centrality and Reach Betweenness are dialog-only: no keyword in
//   Xdpfunc.pas, and their run procedures take no parser argument. Their
//   numbers therefore have to come from PART B as saved datasets, which is why
//   two of the four runs below are Closeness and 2-Mode Centrality rather than
//   anything cheaper.
//
// IF A LINE FAILS
//   Let the rest run and say which line failed. The test harness skips fixtures
//   that are not there, so a partial run is still useful.
// ===========================================================================


// ===========================================================================
// PART A - the scriptable six
// ===========================================================================
// Full precision, saved as datasets. dec only affects what dsp prints; the
// saved ##h/##d pairs keep every digit regardless.

Recordcli = true
dec 8


// --- degree ----------------------------------------------------------------
// Directed input gives Degree, Outdegree, Indegree; symmetric input gives one
// column per relation. The norm keyword divides by n-1 (u.mean over j <> i),
// so these pairs also pin our normalization denominator.

g9_deg_campnet = degree(campnet)
dsp g9_deg_campnet
g9_degn_campnet = degree(campnet norm)
dsp g9_degn_campnet

// sampson: ten relations at once. This is the multi-relation case that decides
// what one-section-per-relation has to produce.
g9_deg_sampson = degree(sampson)
dsp g9_deg_sampson

// newguinea: two relations, the second of which is Opposition. Our
// xdegree(net, relation = "Opposition") has to match column 2 here.
g9_deg_newguinea = degree(newguinea)
dsp g9_deg_newguinea

// isolates: three nodes with degree 0, which is where normalization and the
// statistics block are most likely to disagree with us.
g9_deg_iso = degree(g9_iso)
dsp g9_deg_iso
g9_degn_iso = degree(g9_iso norm)
dsp g9_degn_iso

g9_deg_disc = degree(g9_disc)
dsp g9_deg_disc

// valued: degree is the sum of values, not a count.
g9_deg_baker = degree(baker_journals)
dsp g9_deg_baker

// 2-mode. degree() rejects a non-square matrix - rundegree and runmcent both
// test IsSquare - so this line is expected to fail. It is here to record the
// wording of the refusal, which is what our own message should say.
g9_deg_davis = degree(davis)
dsp g9_deg_davis


// --- betweenness -----------------------------------------------------------
// betw() takes the network and nothing else. One column named Betweenness for a
// single relation, one column per relation for a stack.

g9_bet_campnet = betw(campnet)
dsp g9_bet_campnet
g9_bet_disc = betw(g9_disc)
dsp g9_bet_disc
g9_bet_iso = betw(g9_iso)
dsp g9_bet_iso
g9_bet_sampson = betw(sampson)
dsp g9_bet_sampson
g9_bet_baker = betw(baker_journals)
dsp g9_bet_baker


// --- eigenvector -----------------------------------------------------------
// Two commands, deliberately both. eigencent() is the one the Eigenvector
// Centrality menu item uses and it handles disconnected graphs specially
// (tDisconnectedEigenvector in Xdpmat.pas); eigenvec() is the plainer one.
// Running both on g9_disc is how we find out which one xeigenvector should be.

g9_eigc_campnet = eigencent(campnet)
dsp g9_eigc_campnet
//g9_eigv_campnet = eigenvec(campnet)
//dsp g9_eigv_campnet

g9_eigc_disc = eigencent(g9_disc)
dsp g9_eigc_disc
g9_eigv_disc = eigenvec(g9_disc)
dsp g9_eigv_disc

g9_eigc_iso = eigencent(g9_iso)
dsp g9_eigc_iso

g9_eigc_baker = eigencent(baker_journals)
dsp g9_eigc_baker

g9_eigc_sampson = eigencent(sampson)
dsp g9_eigc_sampson


// --- beta centrality (Bonacich power) --------------------------------------
// Syntax is betacent(<net> <minbeta> <maxbeta> <increment> [multiple] [OUT|in]).
// One explicit beta here, so there is a fixture whose arithmetic we can check
// exactly. The dialog default is a sweep of ten betas from 0 to max
// (uc_BetaCentrality.dfm: from 0, to max, number of betas 10), which the
// command syntax expresses as an increment rather than a count, so the sweep
// itself is left to the dialog.

g9_beta_campnet = betac(campnet 0.1)
dsp g9_beta_campnet
g9_beta_iso = betac(g9_iso 0.1)
dsp g9_beta_iso


// --- PN centrality ---------------------------------------------------------

g9_pn_campnet = pn(campnet)
dsp g9_pn_campnet
g9_pn_iso = pn(g9_iso)
dsp g9_pn_iso
g9_pn_newguinea = pn(newguinea)
dsp g9_pn_newguinea


// --- multiple measures -----------------------------------------------------
// mcent() is the Multiple Measures Suite. It looks recently written, so if your
// build predates it these lines will fail - say so, and treat that as the
// answer to the source-versus-binary question PART B run 1 asks.
//
// Syntax: <out> = mcent(<network>
//           [measures:deg,clo,harm,bet,2bet,eig,beta,kstep,ard,2loc,kcore,frag]
//           [treat:auto|dir|undir] [valued:y|n] [norm:y|n]
//           [beta:auto|<num>] [k:<int>] [undef:zero|avg|max1|n])
//
// The default measure set is everything except harmonic closeness, so the bare
// call is the one to match xcentrality() against.

g9_mc_campnet = mcent(campnet)
dsp g9_mc_campnet

g9_mc_sampson = mcent(sampson)
dsp g9_mc_sampson

// The disconnected case, run four times over the four undefined-distance
// options. This is the most useful block in the file: it tells us what
// xcloseness() should do, independently of the dialog.
g9_mc_disc_n = mcent(g9_disc measures:clo undef:n)
dsp g9_mc_disc_n
g9_mc_disc_max1 = mcent(g9_disc measures:clo undef:max1)
dsp g9_mc_disc_max1
g9_mc_disc_zero = mcent(g9_disc measures:clo undef:zero)
dsp g9_mc_disc_zero
g9_mc_disc_avg = mcent(g9_disc measures:clo undef:avg)
dsp g9_mc_disc_avg

g9_mc_iso = mcent(g9_iso)
dsp g9_mc_iso

// Normalized and unnormalized side by side, so we can see exactly what norm:y
// divides by for each measure.
g9_mc_campnet_norm = mcent(campnet norm:y)
dsp g9_mc_campnet_norm


// --- geodesic distances ----------------------------------------------------
// Not a centrality measure. These let us check closeness and reach arithmetic
// from the distances themselves, rather than trusting two of our own routines
// not to be wrong in the same way.

g9_geo_campnet = geo(campnet)
dsp g9_geo_campnet
g9_geo_disc = geo(g9_disc)
dsp g9_geo_disc
g9_geo_iso = geo(g9_iso)
dsp g9_geo_iso


// ===========================================================================
// PART B - four menu runs
// ===========================================================================
// Please leave every dialog control ALONE. The defaults are the point: I have
// read them out of the .dfm files and want to know whether your build agrees.
// Save each output under the name given, keep one continuous session log for
// all four, and save it as log_menu.txt.
//
//  #  Menu item                          Dataset   Save output as
// --  ---------------------------------  --------  --------------------
//  1  Network | Centrality | Degree      campnet   g9m_deg_campnet
//  2  Network | Centrality | Closeness   g9_disc   g9m_clo_disc
//  3  Network | Centrality | Closeness   campnet   g9m_clo_campnet
//  4  Network | 2-Mode networks |        davis     g9m_2mode_davis
//     2-Mode Centrality
//
// WHY THESE FOUR
//
//  1  Degree on campnet is the confirmation run. From uc_DegreeCentrality.pas
//     I expect the log to read FREEMAN DEGREE CENTRALITY, then nine header
//     lines (input dataset, output degree dataset, output centralization
//     dataset, treat data as, output raw totals, output averages (normalized),
//     allow edge weights, weighted normalization, exclude diagonal), then a
//     matrix titled "Degree Measures" with columns Outdeg, Indeg, nOutdeg and
//     nIndeg, then a second matrix titled "Graph Centralization -- as
//     proportion, not percentage" with columns Out-Centralization and
//     In-Centralization at four decimals.
//
//     If that is what you get, the source tree matches your binary and I can
//     take the other twelve routines from the Delphi without asking you to
//     click through them. If it differs anywhere - a heading, a header line,
//     the centralization wording - your build is older than the tree I am
//     reading, and I need to know that before writing any of them.
//
//  2  Closeness on g9_disc is the one measurement the source cannot settle.
//     uc_ClosenessMeasures.dfm says the dialog has no method selector: it
//     reports Freeman, Valente-Forman and reciprocal-distance closeness
//     together, each with its own options group, and Freeman defaults to
//     ItemIndex 1, "Max observed distance plus 1", with output ItemIndex 2,
//     "Divide totals into N-1". g9_disc has three components, so those choices
//     show up in the numbers rather than only in the dialog. This is also the
//     saved dataset the closeness tests will compare against.
//
//  3  Closeness on campnet, the connected case, so the same options can be
//     checked where no distance is undefined and the three measures should
//     agree with hand arithmetic on g9_geo_campnet from PART A.
//
//  4  2-Mode Centrality on davis is the other dialog-only measurement worth
//     having now. We have decided the normalization denominator for 2-mode data
//     is the size of the opposite mode; this run confirms it and gives the
//     exact headings for both margins.
//
// The remaining dialog-only routines - Reach, Beta Reach, Hubs and Authorities,
// Induced - are deliberately not here. They can wait until their routines are
// being written, and by then run 1 will have told us whether the source can be
// trusted for layout, so all we will need from you is numbers.
//
